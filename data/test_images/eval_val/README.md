# eval_val/ 图像检测指标重算（2026-10-25）

本目录是 `方案 C` 的第一支产物：用 PC 端 onnxruntime 重算图像指标，替代此前写进 README / 报告 / `comparison.csv` 的 **49.8% / 99.5%**。

## 一、结论（可直接引用）

| 集合 | 规模 | 检出率 | mAP@0.5 | 这条数能不能当"泛化性能"用 |
|------|------|--------|---------|--------------------------|
| 训练池有标注图 `raw_pitta` | 1,061 张 / 1,236 框 | **99.2%**（框对 IoU≥0.5：98.6%） | — | 不能，图就是训练图 |
| `images/val` 有标注图 | 220 张 / 251 框 | **95.0%**（209 张） | **86.7%** | **不能**——见下面第 2 条，221/260 张与训练集字节相同 |
| 训练池负样本 `data/neg` | 380 张（321 其他鸟 + 59 纯背景） | 误报 **0/380** | — | 不能，负样本全部进过训练集 |
| 真正没进训练的 val 图（无标注） | 39 张 | **35.9%**（14/39） | — | 唯一可观察的"没见过"信号，但没有 GT 框，只能作参考 |
| 板端翻拍画面 `test_images/board_captured` | 5 张 | **5/5 检出**，最高分 0.869–0.940 | — | 部署链路可用的现场证据，样本太少 |

1. **模型对训练分布拟合得很满**：1,061 张有标注训练图上检出 99.2%，框对 98.6%。
2. **`images/val` 不是独立测试集**：260 张里 **221 张与 `images/train` 的图 MD5 完全相同**（另有 39 张无标注、从未进训练）。也就是说"验证集"是把训练图复制了一份，用它算出的 mAP 只是训练池指标。
3. **真正没见过的 39 张全是难例**（小目标、杂背景、低分辨率），模型只检出 14 张（35.9%）——这比任何"训练池高分"都更能说明泛化能力尚有明显短板。
4. 负样本 380 张里 **0 误报**（最高分 0.0），但同样属于"已见样本"，不能写成"总体特异性 100%"。

## 二、评测口径（写报告时照抄这一段）

- 模型：`best.onnx`（YOLOv8n，单类 `fairy_pitta`，输入 1×3×320×320，输出 1×5×2100）
- 运行：Python 3.13 + onnxruntime 1.31.0，CPU，`num_threads` 默认；无 GPU 加速
- 预处理：letterbox（等比缩放 + 居中填充，填充值 114），BGR→RGB，/255
- 后处理：**输出分数列已经是 0–1 概率（图内已含 sigmoid），直接与 0.52 比较**；不要再用 `src/ps/postprocess.py` 里的 `_sigmoid` 套一次，会改变分数分布
- 阈值：conf **0.52**、NMS IoU **0.45**（与 `src/ps/config.py`、`docs/interface.md` 一致）
- 判定：一张图里存在 ≥1 个 conf≥0.52 的框即算"检出"；mAP@0.5 用单类全点插值，GT 与预测 IoU≥0.5 才算 TP

## 四、复现

```bash
python src/ps/eval_val_onnx.py \
  --onnx "D:/嵌赛/Bird image recognition/best.onnx" \
  --images "D:/嵌赛/Bird image recognition/data/images/val" \
  --labels "D:/嵌赛/Bird image recognition/data/labels/val" \
  --out "data/test_images/eval_val" \
  --seen-positive "data/test_images/positive" \
  --seen-negative "data/test_images/negative"
```

训练池与负样本两组（第 1、3、4 行）用同一脚本的 `run_one()` 逐图调用，控制台输出见 `logs/eval_log_20261025.txt` 第 2–4 节。

## 五、旧数字为什么废弃

| 旧写法 | 实测 | 说明 |
|--------|------|------|
| 检出率 49.8%（649/1,302） | 1,302 张检出 1,090 张 = **83.7%**；其中 1,061 张有标注图 **99.2%** | 同一模型、同一批图、conf 0.52 + letterbox 下复现不出 49.8%。另测"直接拉伸到 320×320"（`infer_board.py` 的预处理方式）也只有 83.7% 水平，说明旧值大概率来自另一条已废弃的脚本/阈值组合，不再引用 |
| 特异性 99.5%（378/380） | **380/380 正确拒绝**，最高分 0.0 | 旧值声称 2 张误报，实测没有 |
| mAP 待实测 | **86.7%**（但为训练池口径） | 数值有了，不能标"独立验证集" |

## 六、还缺什么（这是唯一没被补上的口子）

**一个真正独立的标注测试集**。现有数据里没有任何一张"没进过训练 + 有 GT 框"的图，所以要对外报泛化指标，只能补采：从板端摄像头或现场拍 ≥100 张（含不同距离、光照、遮挡、双鸟同框），人工画框，再跑本脚本。补采前，报告里建议这样写：

> 图像检测在训练池上检出 99.2%、mAP@0.5 86.7%，属训练分布内指标；在 39 张未参与训练的难例帧上检出 14 张（35.9%），说明小目标与复杂背景下的泛化仍有提升空间。独立测试集待补采。
