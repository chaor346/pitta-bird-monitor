# GEMM 公平加速比实测（2026-10-26，PYNQ-Z2）

命令：`sudo python3 e2e_board.py --bench 20`

## 原始输出

```
[音频] bird_sample.wav  sr=32000  采样点=64000
[GEMM] M=12864 K=9 N=16  特征图=64×201
[HW] GEMM overlay 就绪：M=12864 K=9 N=16，DMA C 上限=8388608 字节

======== 公平加速比（板端，各 20 次，中位数）========
硬件 conv1 端到端（DMA搬运+GEMM+反量化；量化循环外只做一次） = 0.0527 s
其中 HLS 核 ap_start→ap_done 纯计算            = 0.0067 s
numpy conv1 单独（A@B+bias+ReLU）               = 0.0310 s
公平加速比 = 0.59x（端到端口径）
纯核加速比 = 4.64x（仅核计算，不含搬运）
最小/最大 硬件端到端 = 0.0526 / 0.0528 s
==================================================
```

## 正确性验证（同一次运行）

```
numpy 全浮点  分数 = 0.997876
硬件 conv1    分数 = 0.997878
conv1 最大误差 = 0.001838（容差 0.02，点数 0/205824）
判定: 仙八色鸫  阈值=0.9850
==== 硬件 conv1 端到端 PASS（与浮点一致）====
```

## 结论

纯核 4.64x 但端到端 0.59x：conv1 计算量太小（numpy 31ms），DMA 搬运 A/B/C 数据占端到端 87%。
正式音频主程序走 numpy，GEMM overlay 仅作硬件加速能力验证。
