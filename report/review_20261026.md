## 二、GEMM bit 版本问题（已按"不追重复测"处理）

`build/gemm/gemm_soc.bit` 是 2026-10-26 重建的版本（MD5 `8240f2dc…`），而 0.997878 /
0.001838 / 6.7 ms 来自 10-25 那一版（`81714b83…`，磁盘上已无副本）。本队确认这份重建版
由 AI 生成、不必再单独追一轮验证，因此处理方式是：**不改数字，只把口径写准**——

- `build/gemm/README.md` 顶部标明数字对应哪一版 bit；
- `verify_gemm.sh` / `gemm_board.py` 接受两个已知版本，未知版本只报"未知"（原来会把自己的
  文件误判成旧版，让人反复覆盖）；
- `comparison.csv` / 报告 / README 的 6.7 ms 一律写明"旧计时口径、核完成时间下界"。

如果哪天顺手有 10 分钟，跑一次 `e2e_board.py` 就能把版本和数字重新对上，不跑也不算错。
