# 音频事件级召回率结果（2026-10-26）

## 这份结果回答什么

“录音里**真实存在**的仙八色鸫鸣声，系统抓住了多少？”
真值不是模型自己的高分窗口（那样是循环论证），而是人耳对着录音逐个确认的
`../truth_draft/events_truth.csv`（9 段、155 个事件）。

## 方法

| 口径 | 定义 |
|---|---|
| 事件级召回（主指标） | 真值事件区间与任一推理窗口**有重叠**，且该窗口 score ≥ 阈值 → 算检出 |
| 窗口级召回（参考） | 窗口中心落在某真值事件内，其中 score ≥ 阈值的比例 |
| 两个阈值 | **0.985**（`pitta-audio.service` 板端实际阈值）、**0.5**（调试/评估口径） |

推理分数来自 PC 端 numpy 全软件链路（`inmp441_predict_time.py` 同一套 mel + CNN），
窗口 2 s、跳 0.5 s。

|---|---|---|
| 0.500（评估口径） | **152 / 155 = 98.1%** | 356 / 373 = 95.4% |
| 0.985（板端阈值） | **151 / 155 = 97.4%** | 338 / 373 = 90.6% |

## 真值是怎么定的

1. `label_audio_events.py` 用 RMS 能量检测出 179 个候选（与模型无关）；
2. 人耳在 `truth_draft/review_events.html` 里逐条判：删除 33 处、改边界/替换 10 处，最终 156 个；
   其中把 `xc188359` 的 4 段 12~20 s 长块改写成具体事件（长块会让“有重叠即命中”失效）；
3. 复核时又剔除 1 个：`xc188359` 60.90–62.28 经确认为环境声（模型分 0.000），
   最终 **155 个事件**。另有两处（`xc188359` 59.30–59.50、`xc183003` 50.60–50.80）
   同属噪声/其他鸟叫，模型却给出 1.000 / 0.999 的高分，已在真值中排除。

## 口径限制（写报告时必须带上）

1. **真值来自录音母本**（Xeno-canto / Macaulay 原始码流），不是板端 32 kHz 实测录音；
   它回答“模型听不听得见”，不回答“板端麦克风现场听不听得见”。
2. 这些录音多为**野外混录**，同一段里常有其他物种/其他个体。真值只保留仙八色鸫，
   因此被删掉的候选里存在模型打出 0.95~1.00 的片段（事件级假阳性线索），
   这部分未计入任何“特异性”数字。
3. 事件级召回按“重叠”判定，对起止边界不敏感（±0.3 s 不影响），因此它衡量的是
   “有没有漏掉这一声”，不衡量“第二秒的定位精度”。
